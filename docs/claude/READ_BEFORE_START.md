# READ_BEFORE_START.md — 開工前必讀

> ⚠️ **這是最高優先級文件。Claude 在對本專案做任何修改之前，必須完整閱讀本文件並遵守。**

## 一、開工前必做（缺一不可）

在動手改任何一行程式碼之前，Claude 必須：

1. **讀完以下文件**：
   - `READ_BEFORE_START.md`（本文件）
   - `TECH_REQUIREMENTS.md`（技術約束，尤其「不動 DB」原則）
   - `TASK.md`（任務清單與優先級）
   - `WORKFLOW.md`（單次任務流程）
   - `DEVELOPMENT_FLOW.md`（整體開發流程）
   - `ISSUES.md`（已知問題）
   - `DEBUG.md`（除錯指南與陷阱）
   - `LOG.md`（近期開發記錄）

2. **確認本次任務**：
   - 屬於哪個 TASK / ISSUE
   - 優先級
   - 是否觸及 **資料庫 / 付款 / 認證** 三大高風險區

3. **向用戶提問**（見第二節）

4. **取得用戶確認後，才可以開始修改**

## 二、必須先問用戶的情況

以下任何一項成立，Claude **必須停手並提問**，不得自行假設：

### 2.1 涉及資料庫

- 需要改 Prisma schema（新增／修改／刪除欄位或 table）
- 需要執行 migration
- 需要批次更新或刪除既有資料
- 需要修改密碼相關欄位
- 任何可能影響既有資料讀取的操作

### 2.2 涉及付款

- 修改 Stripe / PayMe 流程
- 修改金額計算
- 修改 Webhook 或 success handler
- 修改訂單 / 發票 / 收據建立邏輯

### 2.3 涉及認證與授權

- 修改 `middleware.ts` 角色導向
- 修改 NextAuth 設定
- 為 API 加授權（需確認公開 vs 受保護範圍）
- 修改密碼雜湊邏輯（需確認舊資料兼容方式）

### 2.4 需求不明確

- 任務描述有歧義
- 涉及產品決策（例如半成品頁面要補完還是標記暫停）
- 涉及對外可見的行為改變（URL、回應格式）
- 有多種實作方案且各有取捨

### 2.5 發現文件與現況不符

- 程式碼與文件描述不一致
- 發現文件中未記錄的風險
- 發現新的安全問題

## 三、提問格式（建議）

```text
【需要確認】

任務：TASK-XXX

問題：（具體描述）

選項：
A.（方案 A 及其影響）
B.（方案 B 及其影響）

我的建議：（若有）

若不確認，我將暫停不動手。
```

## 四、絕對禁止（不需問，直接不做）

- ❌ 重灌 / 重置 / 清空資料庫
- ❌ 執行 `prisma migrate reset` / `db push --force-reset`
- ❌ 刪除生產資料
- ❌ 未經確認改 schema
- ❌ 未經確認改付款流程
- ❌ 在 response / log / CSV 暴露密碼
- ❌ 批次刪除被註解程式碼而不逐檔確認
- ❌ 在未讀文件的情況下開工

## 五、開工確認簽核（Claude 自我檢查）

在開始修改前，Claude 應在回覆中明確表示：

```text
【開工前確認】

☑ 已閱讀 READ_BEFORE_START.md
☑ 已閱讀 TECH_REQUIREMENTS.md
☑ 已閱讀 TASK.md / ISSUES.md / WORKFLOW.md / DEVELOPMENT_FLOW.md / DEBUG.md / LOG.md
☑ 本次任務：TASK-XXX
☑ 是否觸及 DB：否
☑ 是否觸及付款：否
☑ 是否觸及認證：是（已向用戶確認範圍）
☑ 已向用戶提問並取得確認：（是／無需提問，原因：…）
☑ 準備開始實作
```

**未完成上述確認，不得開始修改。**

## 六、一句話總結

> **先讀完所有 md → 有疑問先問用戶 → 取得確認 → 不動 DB → 最小改動 → 自測 → 記錄。**
